# NicGit decisions

Numbered `N<n>`. Status: *Decided (owner)*, *Decided (agent)* = Claude's call, open to revision, *Proposed*.

| # | Decision | Status | Where |
|---|---|---|---|
| N1 | **NicGit is one integrated forge** (git server + web app) built for NicBim. **Supersedes kimcad D33** ("Hub as an add-on on unmodified Forgejo"). Reasons: a generic forge's merge button runs git's text merge on records, which can corrupt a model; two UIs and auth systems feel like a developer tool; owner asked for a fully integrated server. The kimcad decision log should record that D33 is superseded by NicGit N1 | Decided (owner, 2026-11-03) | [spec](superpowers/specs/2026-11-03-nicgit-design.md) |
| N2 | **Hosted first, on-prem supported.** The owner runs the main hosted service; the same images deploy on premises. Everything private unless made public; customer data protection is a core requirement. Infra lives in `deploy/` until it gets its own repo | Decided (owner) | spec §5, §7 |
| N3 | **`.kim` is a transport format, not a versioned file.** NicGit versions NicBim project repositories. A `.kim` is imported (history kept) and exported (full / latest only / one option) but never stored as a file in git: it would nest a history inside a history, defeat object sharing, and give no useful diff | Decided (owner + agent) | spec §8, [future work](future-work.md#linked-kim-projects) |
| N4 | **`.ifc` files are viewable, not versioned as files.** An IFC can be imported into a project as a new version through the engine's reconciled import (keeps element history when GlobalIds/Tags match) | Decided (owner + agent) | spec §8 |
| N5 | **Stack: Rust server** (axum, tokio, sqlx, Postgres, `kimbim-repo` crate) for everything always-on, **Python engine workers** (kimbim + IfcOpenShell) for heavy BIM jobs, TypeScript/React SPA with That Open Engine. Owner priority: CPU and memory efficiency on limited hardware | Decided (owner: Rust; agent: the split) | spec §6 |
| N6 | **The browser never edits the model, its settings or conflict values.** Conflicts: automatic merge, then **whole-side** (target or source wins everywhere) or **granular** (per conflict, pick a side). Allowed modes, required approvals by count and role, required checks and **protected settings keys** are rules per protected option. An invalid result blocks Combine; the fix is made in the desktop app | Decided (owner) | spec §9 |
| N7 | **What counts as Actions (billable):** customer-configured checks and workflows. Platform jobs needed to display a project (geometry, IFC export for viewing, summaries, merge previews) are not billed as Actions | Decided (agent) | spec §12 |
| N8 | **Revenue lines shape the core:** metering and budgets for Actions, package hosting and AI (via the owner's cloud AI router) are built in, billing integration later. Certifications exist but are out of NicGit's scope | Decided (owner) | spec §12, §13 |
| N9 | **Postgres everywhere**, including on-prem (shipped in the compose file), instead of a SQLite option: one database to test, row-level security for tenant isolation, queue with `SKIP LOCKED` | Decided (agent) | spec §6, §7 |
| N10 | **License AGPL-3.0-or-later** (kimcad D08) | Decided | spec §5 |
| N11 | **Name: NicGit** (may change during market review; not a POC) | Decided (owner) | — |
| N12 | **No KimBim → NicBim rename in this repo.** NicGit reaches the engine through one adapter module per language | Decided (owner) | spec §3 |
| N13 | **Repositories live at `<data>/repos/<project id>/.git`** (a bare git directory named `.git`), so the engine opens them as projects with no engine change. Merge previews and Combine use a temporary worktree HEAD (`Project.open_worktree`) so the store's HEAD never moves | Decided (agent) | `src/repos.rs`, `workers/engine` |
| N14 | **Workers talk to the server over an internal HTTP API** (claim, progress, finish with a shared token) and hold no database credentials. The queue is a Postgres table (`FOR UPDATE SKIP LOCKED`); results are cached forever by content (commit/tree ids) under keys namespaced by project | Decided (agent) | spec §7, `src/api/internal.rs` |
| N15 | **Push validation in a pre-receive hook** (the server binary, `nicgit-server hook pre-receive`): refs only under `refs/heads` and `refs/tags`; protected options need a lead, fast-forward only, never deleted; moving or deleting milestones needs a lead; every new record blob (`objects/ nodes/ loose/ geometry/`) and `kimbim.json`/`settings.json`/`checks.json` must parse as a JSON object | Decided (agent) | `src/git/hook.rs` |
| N16 | **Approvals**: each reviewer's latest, undismissed verdict counts once, with their current role; authors cannot approve their own proposal; any "request changes" blocks; changed protected settings need a lead's approval; new versions on the source dismiss earlier approvals when the rule says so (in the same transaction that moves the head) | Decided (agent) | `nicgit-core/src/approvals.rs` |
| N17 | **`auto` mode refuses settings conflicts too.** The engine would silently keep the target's value; "only combine without conflicts" should mean that | Decided (agent) | `src/api/proposals.rs` |
| N18 | **Settings conflicts resolved to the source** are applied by the worker (it repeats `Project.merge`'s last steps with the chosen settings) until the engine accepts settings resolutions | Decided (agent); engine gap in future work | `workers/engine/nicgit_worker/handlers.py` |
| N19 | **Actions are the checks an option's rule requires** (`schema`, `ids`, `clash`, `model` from the engine): run on pushes to that option and on proposal source heads, required to pass before Combine, metered as `action_seconds` (rounded up, at least 1), refused when the hard budget is spent | Decided (agent) | `src/actions.rs` |
| N20 | **Budgets are spending caps the account admin sets** (soft and hard per usage kind, per calendar month). Storage is a gauge (latest sample per project); the rest is summed. Hard limits stop Actions and AI only | Decided (agent) | `src/metering.rs` |
| N21 | **NicGit defines the AI router contract** (`POST /v1/chat`, `{text, usage.units}`), sends only the engine's structured change list, caches answers per proposal state | Decided (agent) | [ai-router.md](ai-router.md) |
| N22 | **The web viewer uses web-ifc + three.js directly** (not That Open components), one mesh per element tagged with its GlobalId; spaces, openings, annotations, virtual elements and grids are hidden unless selected | Decided (agent) | `web/src/viewer` |
| N23 | **BCF 3.0 written and read in Rust.** Camera stored in the viewer's Y-up coordinates and converted to Z-up on export; the viewer's re-centring of large models is not undone, so exported cameras are approximate while selections are exact | Decided (agent) | `src/bcf.rs` |
| N24 | **Legacy `.kim` files from before the KimBim rename** (`kimcad-file.json`, `kimcad/1` records) are refused with an explanation: the engine has no backward compatibility (kimcad D94) | Decided (agent) | `workers/engine/nicgit_worker/transfer.py` |
| N25 | **Web toolchain pinned to Vite 6 / Vitest 3 / TypeScript 5.8** because the machine's Node 22.3 is below Vite 8's floor; move up with Node | Decided (agent) | `web/package.json` |
| N26 | **Agent decisions N1–N25 reviewed and accepted**, including the AI router contract (N21) and the name (N11) | Decided (owner, 2026-11-04) | — |
| N27 | **Playwright only when sandboxed, on Chromium releases not affected by known vulnerabilities.** It has known vulnerabilities, so it is not an ordinary dev dependency | Decided (owner, 2026-11-04) | `web/e2e` |
| N28 | **Google OAuth is the only sign-in for now; anyone can join.** No password sign-in, including on-prem, for now. Git keeps using access tokens. The site admin is named by email in server config, not by being first to sign up | Decided (owner, 2026-11-04) | not built |
| N29 | **Postmark for email; no password reset and no 2FA** | Decided (owner, 2026-11-04) | not built |
| N30 | **A job reaches only its own project's files.** One process per job, a token per job, files fetched over HTTP, no shared volume, and nothing of a job survives into the next: in a container every other process is stopped and the writable folders cleared when a job ends, because a leftover process under the same user could otherwise read the next job's token | Decided (owner, 2026-11-04) | `workers/engine/nicgit_worker/`, `api/job_files.rs`, ops.md |
| N31 | **Next step after the blockers is a private pilot with one real office**, then the package registry | Decided (owner, 2026-11-04) | — |
| N32 | **Git hosting stays in the same deployable, behind one repository module.** Separate later with a role flag on the same binary (`--role git`) once clones visibly slow the app or repositories need their own machine | Proposed (agent; owner raised the split) | — |
| N33 | **Storage is limited per file, project and account, to be reassessed after the pilot.** Defaults: 512 MB a file, 2 GB a project, 5 GB an account. A full project can still be read and can still finish a Combine, and an upload that does not fit is refused before a project exists. Agent's additions, because the limits are otherwise easy to get around or do not cover worker time: at most 100 projects an account and 3 organisations a person; cached exports limited per project, oldest dropped first and not counted against the account since they can be remade; the account with the fewest running jobs goes first; a job stops after 60 minutes and fails after losing its worker 3 times. Several Google accounts can still get several allowances, so watch the disk. Budgets' rule that a hard limit never blocks pushing still holds: this is a separate, flat limit | Decided (owner: the three sizes, values by agent; rest agent, 2026-11-05) | `limits.rs`, `tests/limits.rs` |
| N34 | **User names and commits do not expose the email address.** A new user name comes from the Google display name (`Ana García` → `ana-garcia`), or `user-<random>` if that gives nothing usable. It can be changed in account settings, up to 3 times; the old name stays reserved so nobody else can receive what was meant for its owner, with no redirect. Commits NicGit makes for a person (imports, Combine, milestones) use `<account id>@users.noreply.nicgit`. Commits a person pushes carry whatever their own git is set to | Agent, on the owner's "apply correct fixes" (2026-11-05) | `api/auth.rs`, `auth/mod.rs`, `tests/limits.rs` |
| N35 | **The workers' API has its own address, which is never published.** `/internal/*` is served on `NICGIT_INTERNAL_BIND` (default `127.0.0.1:3001`) and not at all on the public port, so it no longer depends on a proxy rule | Agent, on the owner's "apply correct fixes" (2026-11-05) | `app.rs`, `deploy/compose.yaml` |
| N36 | **Accepted for now: a job taken over by a crafted model can lie about its own project.** Damage is confined to that project: another customer's data cannot be reached (N30). It can report a wrong check or compare result, or make a Combine commit with the wrong content, only in a project where the attacker can already push and only when a lead combines. The server does not trust what it can check itself: time billed and the version named come from its own records, and refs from the repository. Closing the rest would need a second, independent engine run | Agent, on the owner's "apply correct fixes" (2026-11-05) | `actions.rs`, `events.rs`, `api/internal.rs` |
| N37 | **Google-only on premises stays as decided (N28).** It means an on-premises server and its users must be able to reach Google. Nothing changed; a customer who cannot would need another sign-in built first | Owner's N28, noted by agent (2026-11-05) | ops.md |
