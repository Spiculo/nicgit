# NicGit v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working NicGit: Rust forge server with git smart-HTTP hosting of KimBim projects, accounts/orgs/roles, a web app to view versions in 3D, compare, propose, approve and Combine (engine merge), BCF-style issues, milestones, `.kim`/`.ifc` import/export, metering hooks and AI summaries through a router client.

**Architecture:** `nicgit-server` (axum + sqlx/Postgres) owns auth, tenancy, git transport and forge data, and reads git through the engine's `kimbim-repo` crate. Heavy BIM work runs in Python engine workers (`workers/engine`, kimbim + IfcOpenShell) that claim jobs from the server over an internal HTTP API. The React SPA (`web/`) talks JSON to the server and renders IFC with web-ifc + three.js.

**Tech Stack:** Rust 1.97 (axum 0.8, tokio, sqlx 0.8 postgres, argon2, serde, tower-http), Postgres 16 (docker, port 5434 for dev), Python 3.12 from kimcad's pixi env, React 18 + Vite + TS, three.js, web-ifc.

**Spec:** `docs/superpowers/specs/2026-11-03-nicgit-design.md` (+ `docs/decisions.md`, `docs/future-work.md`)

## Global Constraints

- License AGPL-3.0-or-later; SPDX header `// SPDX-License-Identifier: AGPL-3.0-or-later` (or `#` form) on every source file.
- Engine is never forked: Python workers import `kimbim` from `../kimcad/python`; Rust links `../kimcad/crates/kimbim-repo`. Engine gaps get a kimcad change or are recorded in `docs/future-work.md`.
- Server repo layout on disk: `<data>/repos/<project-uuid>/.git` (bare git dir named `.git`, HEAD → `refs/heads/main`), so `kimbim.project.Project.open(<data>/repos/<uuid>)` works unchanged.
- The browser never edits a model. Server writes to projects only via Combine and imports.
- Conflict modes: `auto`, `whole:ours` (target wins), `whole:theirs` (source wins), `granular` (per conflict id → `ours|theirs`). UI words: *target option* / *source option*.
- Roles ordered: `viewer < reviewer < member < lead < admin`.
- Projects private by default. Any route on a project the caller can't read returns **404**, never 403.
- UI copy in EN and ES; architect words (project, version, design option, proposal, combine, milestone).
- Never run git's text merge on records. Pushes to protected options must be fast-forward and by `lead`+.

## Review Focus

1. **Foreign account access** — every `/api/projects/{owner}/{name}/…` route and git URL as a non-member of a private project → 404. Test: `isolation.rs::foreign_user_gets_404_everywhere` (Task 3/4).
2. **Push of a non-KimBim / corrupt record** (conflict markers, invalid JSON in `o/…`) → rejected by pre-receive with a readable message. Test: `git_http.rs::push_rejects_invalid_record` (Task 4).
3. **Head moved between approval and Combine** — source got new versions after approval → approvals dismissed, Combine blocked until re-approved. Test: `proposals.rs::new_push_dismisses_approvals` (Task 8).
4. **Huge uploads / zip bombs** — `.kim` over the size limit or unpacking beyond 20× → refused. Test: `test_jobs.py::test_import_kim_rejects_bomb` (Task 9).
5. **Empty project** (no versions yet) — overview, versions, compare pages render an "empty / push your first version" state, no 500. Test: `projects.rs::empty_project_overview` (Task 5).

### Task 4: Git smart HTTP + pre-receive hook + post-push processing

**Files:** `src/git/{mod.rs,http.rs,hook.rs,validate.rs}`, `src/main.rs` (subcommand `hook pre-receive`); tests `tests/git_http.rs`.

**Interfaces — produces:** routes `GET /{owner}/{slug}.git/info/refs?service=git-upload-pack|git-receive-pack`, `POST /{owner}/{slug}.git/git-upload-pack`, `POST …/git-receive-pack`. Auth: Basic (any username, PAT as password) or anonymous for public read; `WWW-Authenticate: Basic realm="NicGit"` on 401 (private projects: 401 when anonymous so git prompts; 404 when authenticated non-member). Spawn `git <service> --stateless-rpc [--advertise-refs] <repo>/.git`, pipe body (gunzip if `Content-Encoding: gzip`), pass `GIT_PROTOCOL`. Env to hook: `NICGIT_ROLE`, `NICGIT_PROTECTED` (comma list from `option_rules`), `NICGIT_USER`. Hook (`nicgit-server hook pre-receive`): for each `old new ref` line: refuse deleting/non-ff (`git merge-base --is-ancestor`) on protected unless role ≥ lead AND fast-forward; refuse any push to protected unless role ≥ lead; refuse refs outside `refs/heads/*` and `refs/tags/*` (`refs/proposals/*` reserved); validate changed blobs under `o/ n/ l/ g/` via `git diff-tree -r --no-commit-id old new` (or `ls-tree` for new refs) → each blob must parse as JSON object containing `"k"`; `settings.json` must parse as JSON. Messages prefixed `NicGit:`. After receive-pack completes, server diffs ref snapshot before/after → `events::on_push(project, user, updates: Vec<RefUpdate{name, old, new}>)` → activity rows, `usage_events(storage_bytes)` sample, proposals head update (Task 8), enqueue `summary` jobs for new heads.

- [ ] Tests (real `git` CLI against the spawned server, repo built with `kimbim`-shaped blobs written by plain git): `clone_empty_project`, `push_then_clone_same_tree_hash`, `push_requires_auth_private`, `anonymous_clone_public`, `push_rejects_invalid_record`, `protected_option_requires_lead`, `push_records_activity`.

- `import_kim {upload}`, `import_ifc {upload, option, message}` (Task 9).
